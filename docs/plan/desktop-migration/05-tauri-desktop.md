# 05 — Tauri desktop application

**Status:** draft · **Target:** Tauri 2.12.x · **App:** HRAgents Desktop (`com.hragents.desktop`)

The desktop edition replaces the FastAPI/Postgres server with an in-process Rust core and embedded
SQLite. One single-role HR team per install (1–3 local accounts, §06). No localhost HTTP, no Python,
no browser tab.

## 1. Why Tauri 2.12

- **Size:** 15–30 MB installer and ~150–200 MB idle RAM (Electron: 80–150 MB / 250–400 MB) because
  the OS webview is shared — WebView2, WKWebView, or WebKitGTK 4.1.
- **Rust integration:** `hragents-core` is a workspace crate linked in-process — no sidecar,
  bundled Python/Node, second IPC protocol, extra signing target, or 200–600 ms startup.
- **Updater and capabilities** are first-party: signed manifests, allowlisted commands, and an
  unprivileged webview.
- **Version note:** 2.12.x is the current stable line (Nov 2026). **Tauri 3 is not stable**; do not
  adopt previews. Pin `tauri`/`tauri-build` 2.12, `@tauri-apps/api` 2.12.x, plugins 2.x; commit
  both lockfiles and build with `--locked`.

## 2. Process and thread model

| Layer | Runs on | Responsibility |
|---|---|---|
| UI | webview process | React, rendering; no DB/FS/network |
| IPC | Tauri main process | allowlist, serialize, route |
| Core | main process, Tokio | auth, validation, deterministic logic, audit |
| DB writer | one task + mpsc | serialized transactions |
| DB readers | pool of 4 | queries, WAL snapshots |
| Jobs | Tokio tasks | import, scoring, export, backup, sync |

- **No HTTP listener, no loopback port, no CORS.** The webview reaches Rust only through
  `invoke()` and `Channel`. `tauri-plugin-shell` is not installed (no shell tools); `opener` accepts
  only allowlisted `https:`/`mailto:` URLs.
- **Commands** are `#[tauri::command] #[specta::specta] async fn`. `tauri-specta` generates
  `src/lib/ipc/bindings.ts`; CI fails on drift (`cargo test export_bindings && git diff --exit-code`).
- **Async discipline:** parsing, hashing, XLSX/PDF, and SQLite run on `spawn_blocking` or DB tasks;
  no lock is held across `.await`.
- **Events** are coarse: `db://changed {table, ids}` invalidates queries; `update://state` drives the
  updater UI; job progress is throttled to 10 Hz; token streaming uses `tauri::ipc::Channel<String>`.
  Payloads carry IDs, never PII.
- **Jobs** persist in `jobs` (`queued/running/succeeded/failed/cancelled`), are claimed atomically,
  resume after crash, and allow one worker per kind. Quit waits ≤10 s.
- **Single-instance plugin** forwards argv/deep links to the running app and exits 0 — two processes
  must never write one database. A renderer crash reloads the shell; Rust keeps the DB consistent.

## 3. Window and app UX

| Area | Behavior |
|---|---|
| Window | min 1024×700 (rail collapses below 1100), default 1280×860, restore geometry/maximized/display |
| Menu | Native menu: app menu (macOS); File (Import, Export, Backup, Lock, Quit); Edit; View; Window; Help |
| Shortcuts | `Cmd/Ctrl+K` palette · `Cmd/Ctrl+N` new · `Cmd/Ctrl+O` import · `Cmd/Ctrl+Shift+L` lock · `Cmd/Ctrl+,` settings |
| Tray | Show/Hide, Lock, pending count, Check updates, Quit; left-click toggles |
| Notifications | unfocused only, no PII (“3 items need you”), click routes, quiet hours |
| Drag-drop | CVs/imports; validate extension, MIME, size ≤20 MB; stage, then preview — never auto-commit |
| Files/links | `.hrpacket`/`.hrbackup` open a preview; `hragents://candidate/{id}` routes after auth; no action execution |
| Offline | local-first; badge only for unreachable LLM/integrations; outbound sends queue in an outbox |
| Auto-lock | Rust timer, default 15 min, 60 s warning; lock on sleep/session-lock/screensaver; privacy curtain |
| Quit | Windows/Linux: close quits, confirm if a job runs; macOS: close hides, `Cmd+Q` quits; tray-hide opt-in |
| Crash | unclean-shutdown detection and safe mode (§8) |

Auto-lock is authoritative in Rust because background tabs throttle JS timers. Lock zeroizes session
key material, closes the DB pool, and revokes the token (§06); unlock needs the password, while
biometrics may satisfy re-auth.

## 4. Frontend integration

| Package | Version | Use |
|---|---|---|
| React | 19.3.1 | UI, concurrent features |
| Vite | 8.3.5 | build, `@tailwindcss/vite` |
| TypeScript | 7.0.2 | strict, `noUncheckedIndexedAccess` |
| Tailwind | 4.3.3 | tokens from `styles/theme.css` only |
| TanStack Query | 5.x | server-state cache over IPC |
| Zustand | 5.x | ephemeral UI state only |
| react-router | 8.x | hash router under the asset protocol |
| i18next | 26.x | EN/ID, persisted locale |

- **One IPC client**, generated by tauri-specta and wrapped in `src/lib/ipc/client.ts` (error
  mapping, auth-lock handling, tracing). `fetch`, `axios`, and OpenAPI clients are banned in `src/`
  by lint rule; there is no HTTP API.
- **Query wrappers:** `queryOptions` factories with stable keys, `staleTime` 30 s, `gcTime` 5 min,
  no cache persistence (PII must not reach IndexedDB). `db://changed` invalidates affected keys.
- **Mutations** call one command then invalidate. Optimistic updates only for reversible local
  changes (stage, tag, note) with snapshot rollback; payroll sign-off, erasure, and rejection
  override wait for the audit receipt.
- No PWA/service worker in the desktop build. Zustand never stores server data. Route-level code
  splitting via `lazy()` + Suspense; XLSX/PDF load on demand. Dates come from Rust’s business-day
  logic, not the OS clock.

## 5. Packaging and distribution

| Target | Artifact | Notes |
|---|---|---|
| Windows 11 / 10 22H2 | NSIS `.exe` (updater), MSI (enterprise) | per-user default, per-machine optional |
| macOS 13+ | universal `.dmg` | hardened runtime, notarized, stapled |
| Linux | `.AppImage`, `.deb` | Ubuntu 22.04+, WebKitGTK 4.1 |

- **Size:** installer ≤35 MB hard cap (target 22–30 MB), installed ≤90 MB, delta ≤10 MB, initial JS
  ≤250 KB gzip. WebView2 uses `embedBootstrapper` (+~1.8 MB), which downloads the shared Evergreen
  runtime; the ~130 MB offline runtime bundle is not shipped.
- **Signing:** Authenticode (Azure Trusted Signing or OV) + RFC 3161 timestamp; Apple Developer ID,
  `notarytool`, staple; AppImage minisign; `.deb` checksums. Unsigned dev builds refuse to update.
- **Updater:** `tauri-plugin-updater`, signed `latest.json` per channel, minisign pubkey pinned in
  `tauri.conf.json`, HTTPS only. Endpoints:
  `https://updates.hragents.id/{stable|beta}/latest.json`.
- **Channels:** `stable` default, `beta` opt-in, nightly internal. Manifests carry `rollout` 0–100;
  clients bucket on `SHA-256(device_id + version)` and follow 5% → 25% → 100%. A signed
  `yanked_versions` list prompts rollback.
- **Rollback:** Tauri cannot downgrade in place. Keep the previous installer in `updates/cache/`
  for 7 days; “Roll back” reinstalls it, restores the pre-update backup, and re-verifies audit. A
  failed migration does this automatically.

## 6. Install, update, backup

First-run wizard (works offline once WebView2 is present): language → company profile (name, address,
optional NPWP, `Asia/Jakarta`, IDR) → first operator → recovery key (show once, confirm 4 words,
acknowledge loss) → data location → optional demo data → optional providers (skip = offline mode).

| OS | Data root |
|---|---|
| Windows | `%LOCALAPPDATA%\HRAgents` |
| macOS | `~/Library/Application Support/com.hragents.desktop` |
| Linux | `~/.local/share/hragents` |

Contains `<company>/hragents.db` plus `backups/`, `logs/`, `imports/`, `cache/`, `crash/` (§04).
**Portable mode** is opt-in (`portable.flag` beside the exe → `.\data`): no installer/registry, but
the key remains in the OS keychain, so moving machines needs the recovery key. Supported, not
recommended for shared USB.

- **Migrations** are forward-only, versioned in `PRAGMA user_version` + `schema_migrations` (§04),
  one transaction each. A newer schema than the binary refuses to open. Every update backs up first,
  then migrates, `quick_check`, and verifies audit; failure restores and relaunches the cached
  previous version.
- **Backups:** first run, daily (keep 7), before update/restore/rekey/erasure, and manual. Internal
  runs are SQLCipher `.db` copies verified by `rusqlite::backup` (§04); a manual export writes a
  sealed `.hrbackup` (snapshot + manifest with schema, counts, audit head, SHA-256). Both are
  verified at creation and restore.
- **Restore** never merges: verify signature/hash/schema → password (plus recovery key if foreign)
  → snapshot current DB → restore to temp → verify audit → atomic swap → restart. Accounts and
  audit history survive.
- **Uninstall keeps data by default** and prints the path. Deletion needs a checkbox, typed
  confirmation, and the recovery key. Keychain items, autostart, deep-link, and file-association
  registrations are removed; external backups are untouched.

## 7. Performance

| Metric | Budget (p95, 4-core/8 GB SSD) |
|---|---|
| Cold start → interactive | ≤1.5 s |
| First paint | ≤500 ms |
| Route transition | ≤100 ms |
| Simple command | ≤50 ms |
| List (10k rows, 50/page) | ≤250 ms |
| Memory idle / active | ≤180 / ≤350 MB |

- **Release profile:** `opt-level = 3`, `lto = "fat"`, `codegen-units = 1`, `strip = "symbols"`,
  `panic = "abort"`, `incremental = false`; tests keep unwind. `panic=abort` removes landing pads
  but forbids `catch_unwind` — all fallible paths return `Result`.
- **Startup:** native splash immediately; main window hidden until React mounts and the first query
  resolves (or 300 ms); updater check deferred 30 s after idle.
- **SQLite:** WAL, `synchronous=NORMAL`, `mmap_size=256MB`, `cache_size=-64MB`,
  `temp_store=MEMORY`, `foreign_keys=ON`, `busy_timeout=5000`; keyset pagination, FTS5, batched
  writes, one command returns each screen’s aggregate (no N+1 over IPC).
- **JS:** no moment/lodash/chart bundle on first route; charts/XLSX/PDF dynamic; virtualize above
  200 rows (`@tanstack/react-virtual`); selectors + `memo`; `useDeferredValue` for search; bundle
  budget enforced in CI.

## 8. Observability and crash

- `tracing` JSON logs, daily rotation, 14 files / 50 MB cap, redaction (NIK, NPWP, phone, email,
  tokens, paths), level switchable in Settings.
- No telemetry or analytics by default. Network calls are only: update check, configured LLM
  providers, opt-in crash-report upload, optional integrations. Settings lists network activity.
- Panic hook records version, thread, backtrace hash, and last 50 trace events, then aborts; no DB
  content, CV text, or keys. OS crash dumps are disabled where policy allows.
- On unclean start: `quick_check`, audit verify, orphaned-job recovery, banner offering diagnostics
  or restore.
- **Diagnostic bundle** (`.hrdiag`): logs, OS/WebView/app versions, schema and migration history,
  audit head + last 100 event hashes, redacted config, integrity result, disk space. The user
  reviews the file list before export; upload is opt-in.

## 9. Acceptance criteria and risks

- [ ] Cold start ≤1.5 s, first paint ≤500 ms; nightly benchmark.
- [ ] Installer ≤35 MB on all targets; no full WebView2 runtime, Python, or Node payload.
- [ ] Second launch focuses the running window and exits 0; no second DB writer.
- [ ] Bindings drift and `fetch`/OpenAPI use fail CI.
- [ ] Deep links and file associations open a preview, never execute.
- [ ] Auto-lock fires from Rust while backgrounded; sleep locks immediately.
- [ ] Bad update signature is rejected; rollback restores version and backup.
- [ ] Uninstall retains data and prints the path; destructive mode is opt-in.
- [ ] Diagnostic bundle contains no PII or secrets (fixture test).

| Risk | Impact | Mitigation |
|---|---|---|
| WebView2 drift/missing | blank window | bootstrapper, version check, guidance |
| WebKitGTK bugs | broken Linux UI | CI on 22.04/24.04, smoke, support tier |
| SQLCipher + WAL cost | slow lists | benchmarks, cache tuning, keyset paging |
| Large migration overruns quit | bad state | backup, transactional migration, resume |
| Signing key loss | no updates | HSM, dual control, rotation drill |
| Updater supply chain | RCE | pinned key, signed manifest, staged rollout, SBOM |
